# `config.json` — every key, what it does, and who reads it

The release zip ships one full `config.json` at its root and a client-only copy in each game's
folder under `games\`, cut from the root one at release time so they never disagree. Both programs
read their own half: `meshghost.exe` (the client, started for you by your game's mod) reads the
`client` section, and `meshghost-server.exe` (run by whoever hosts) reads the `server` section. A
few `client` keys are read by the game's mod itself rather than by `meshghost.exe`, and the table
says which. A key that is absent keeps its built-in default, so a config file only ever overrides
what it mentions. The root file is
[`packaging/release/config.json`](../packaging/release/config.json) and the walkthrough is the
`README.txt` beside it; this page is the reference those two point at. Which copy a game reads is
in that game's own `README.txt`: TEVI and Pseudoregalia read the one you copied into the game's
folder; Emerald and Crystal run from the release folder itself and nothing is copied.

Everything below is taken from the two programs' own config definitions (`cmd/meshghost/main.go`,
`cmd/meshghost-relay/main.go`), the mods' own config readers, and the shipped file, on 2026-09-06.

## `client` — read by `meshghost.exe`

| Key | Shipped value | What it does |
|---|---|---|
| `connect_to` | `127.0.0.1:7777` | The host's address and **tcp** port. Only the tcp port is ever needed: the handshake is tcp and asks the server what else it serves. |
| `transport` | `auto` | What the session moves to *after* connecting: `tcp` stays, `udp` or `quic` upgrade if the server offers them, `auto` takes the best on offer. Asking for one the server lacks degrades to tcp, never to a timeout. |
| `tls` | `auto` | Encryption of the tcp legs, including the handshake that carries the room code: `off`, `auto` (plaintext fallback with a log warning) or `required` (refuse an unencrypted server). |
| `tls_fingerprint` | empty | Optional pin of the server's certificate: the SHA-256 the server prints at startup, given to you by the host. Empty means encrypted but not authenticated. **Setting it forces `tls` to `required` for that session** (since 2026-09-07, logged when it happens): under `auto`, "the pin did not match" and "this relay cannot do TLS" arrive as the same error, and `auto`'s job is to fall back to plaintext on it — so a pin under the shipped default turned detection of an interfering relay into an automatic downgrade to it. A pin therefore cannot be combined with `transport: udp`, which is refused at startup. The server regenerates its certificate on every restart, so a pin has to be re-copied. |
| `room` | `default` | A label, not a password: everyone who wants to see each other uses the same one. |
| `room_code` | empty | The optional actual secret. If the host set one, you need it. |
| `name` | empty | Your nametag, drawn above your ghost for other players. Empty means no tag at all. Sanitized (control and direction-override characters removed) and capped at 24 characters; not an identity, two players may share one. |
| `name_color` | `#A89975` | Hex colour for the box behind your nametag, ignored without a `name`. Blank means no box; a value that is not a hex colour is ignored and never stops you connecting. |
| `ghost_collision` | `disabled` | Your own preference, and it only works in the restrictive direction: `disabled` turns ghost collision off for you whatever the host chose; `enabled` accepts the host's setting. (As of 2026-09-06 no shipped adapter honours it yet: `agent_docs/plans.md`, "Settings: defined once".) |
| `ghost_range_throttle`, `ghost_range_far`, `ghost_range` | `6500`, `8500`, `10500` | Read by the game's mod (Pseudoregalia as of 2026-09-06), in that game's own units: how far a ghost can be before it is drawn cheaper. Beyond the first, its animation runs at the engine's reduced rate; beyond the second, its pose freezes while it still moves; beyond the third it goes dormant — model hidden and ticking nothing, only its nametag left so you know someone is there, and back in one frame when it comes closer. The defaults are one player's read of a long hall in the lower castle: animation readable to ~6,400 units, nothing worth drawing past ~10,500. `0` disables that step. Re-read while the game runs, so you can tune them without a relaunch. |
| `autostart` | `true` | Read by the game's mod, not by `meshghost.exe`: whether the mod starts a hidden client for you when the game launches and stops it when you quit. `false` means the mod starts nothing and uses whichever client is already running — the supported way to run MeshGhost when an antivirus objects to a game launching a second program, or when you want to see the client's window. The older `MESHGHOST_NO_AUTOSTART` environment variable still counts as `false`. |
| `local_game_bridge` | `127.0.0.1:7778` | Where your game's mod talks to this client. Never leaves the machine. Mods walk a small range upward from here so two games on one PC do not collide. |
| `interp` | `450ms` | How far behind real time OTHER PLAYERS' ghosts are drawn, which is what makes their motion smooth. Never set it below your connection's jitter; each game's mod may ship its own value. |
| `offline` | `false` | Play alone on purpose: no relay is contacted, no room is joined, and nobody else appears. Recording, replays and chasers all still work, and your game connects to this client exactly as always. Without it, a client that cannot reach a relay keeps retrying and says so in its log. |
| `local_interp` | `25ms` | The same idea for a ghost your own client invented -- a replay or a chaser -- and a different number for a different job: nothing about it crossed a network, so it is drawn a sample interval or two behind its own schedule rather than `interp` behind. Raise it and a chaser set to 3s falls further back than 3s; zero makes it stutter instead of gliding. **When to raise it anyway:** a ghost is drawn from samples, and this is how long it waits for the NEXT one before giving up and holding the last -- so it has to be wider than the gap between samples, or the ghost freezes and jumps instead of gliding. 25ms covers any feed at 40Hz or better. A CHASER is fed by your own game, so this is about YOUR frame rate right now; a REPLAY is fed by the file, so it is about the frame rate of whoever RECORDED it, and no setting on the watcher's machine changes what is in the clip. Rule of thumb: two sample intervals, i.e. about `2000/fps` ms -- `50ms` for a 40fps recording, `100ms` for 20fps. `dev-scripts/replay-cadence.py` prints a clip's actual spacing so this is a measurement rather than a guess. |
| `max_receive_hz_per_player` | `0` | The most updates per second you want from each *other* player. `0` means whatever the server sends. Per player, not a total. |
| `replay` | `{"record_on_launch": false, "save_last": "30s", "start_delay": "0s", "seek": "5s", "split_times": false, "delta": true, "gzip": false, "inputs": false, "name": "", "color": "", "indicator": true, "indicator_color": "#EE4B2B", "indicator_timer_color": "#FFFFFF"}` | Recording and playback (2026-09-03). `record_on_launch` writes every session to the `replay` folder beside this file, from your first in-game moment to quitting; `save_last` is how much recent play the save-last key writes out after the fact; `start_delay` is how long after you are in the game a replay ghost starts (a file's own `start_delay` overrides it); `seek` is one rewind or fast-forward press; `name` and `color` label the clips you record -- what a replay ghost's nametag shows -- and blank uses your own `name`/`name_color`, so you never have to edit a file's header just to label it; `delta` (on) writes only the values that changed since the previous sample and carries the rest forward when the clip loads -- about 4x smaller, still plain text, and the header you edit is untouched; `gzip` (off) compresses the whole file to `.ndjson.gz`, roughly 39x smaller but not editable and unreadable to most tools if the game crashes mid-recording and read identically -- turn it off if you want a file you can open in a text editor; `inputs` (off) also records what you PRESSED, as a separate file in `replay/inputs/` beside the recording -- a record of the run's input rather than of where your character was, which stays true however the rest changes, and which is what an input display or a debugging session would read. It never plays back as a ghost, and the folder it lands in is one neither replay key looks at, so a track can never be picked up as a clip. Needs a game mod that sends its inputs: Pseudoregalia's does from the 2026-09-08 build (unreleased as of that date), the other three do not yet, and with one that does not this costs nothing. `split_times` (off) puts how far behind or ahead of the ghost you are on its nametag, e.g. `PB +1.2s`; `indicator` (on), `indicator_color` and `indicator_timer_color` are read by the game's mod, not by `meshghost.exe`, and control the on-screen mark a mod draws while you are recording — a coloured square with a timer beside it — so a recording is never running unnoticed; a mod that has no such indicator ignores all three. Drop a file into `replay/active/` and it plays as a cosmetic ghost; nothing here names a file. That folder reads `.ndjson`, `.ndjson.gz` and `.zip` -- a zip is the easy way to send a clip to someone, needing no tool to make and none to open, and one holding several recordings plays all of them, one ghost each. |
| `chaser` | `{"enabled": false, "count": 1, "delay": "3s", "spacing": "2s", "name": "", "color": "", "contact": false, "spawn_delay": "0s"}` | Your own past following you: `count` ghosts, the first `delay` behind and each next one `spacing` further back. No cap on `count` or on files in `replay/active/` (since 2026-09-06): as many as your game can draw, up to the 512 seats a room has in total. A chaser appears only once you have been moving for `spawn_delay` (`0s` = its own delay), so none spawns on top of you at the start. Always cosmetic, whatever `ghost_collision` says. `contact` tells a game's mod a chaser may hurt on touch; no shipped mod honours it yet. |
| `input_display` | `{"player": false, "ghost": false, "always": false, "background": true, "rows": 10, "size": 22, "unit": "cs", "count_side": "left", "player_side": "left", "ghost_side": "right"}` | An on-screen input history, fighting-game style: each row is what was held and for how many frames, newest on top (2026-09-08; Pseudoregalia only so far). `player` shows your own, on `player_side`; `ghost` shows a replay ghost's from the input track recorded beside its clip (`replay.inputs`), on `ghost_side`, and takes the player's side when the player's is off; `always` (off) shows the player's even when no recording is running; `background` (on) draws the translucent panel behind the rows; `rows` and `size` are how many rows and the text size; `unit` is what a row's count measures -- `cs` (hundredths of a second, comparable between players at different framerates), `ms`, or `frames` (engine frames, the only unit that can show a single-frame press); `count_side` puts the count before (`left`) or after (`right`) the inputs. Both ship off; a mod without the display ignores the whole section. |
| `hotkeys` | `{"record_toggle": "ctrl+shift+F9", "save_last": "ctrl+shift+F10", "replay_last": "ctrl+shift+F11", "replay_restart": "ctrl+shift+F5", "replay_rewind": "ctrl+shift+F6", "replay_fast_forward": "ctrl+shift+F7"}` | System-wide keys the client registers itself, so they work with the game focused. `ctrl`, `shift`, `alt` plus one key (F1–F24 except F12, letters, digits, space, home, end, page up/down, insert, delete); an empty value unbinds. Windows only; a chord another program already owns is skipped and the log says so. |

Also in the `client` section, shipped at values you should not need to change: `game` (empty; announced by the mod, not set by you), `game_version` (empty), `min_send` (`0s`), `keepalive` (`250ms`; how often an unchanged state is re-sent, `0` sends every frame), `extrapolate` (`0s`; a prediction window, `0` holds the newest sample), `curve` (`linear`; or `catmull-rom`), `predict` (`damped`; how a ghost is carried past its newest sample when `extrapolate` is on — `linear` continues the last velocity, `accelerated` fits the curve of a jump from three samples but amplifies jitter, `damped` is linear prediction scaled back on any axis whose velocity is changing, the middle ground), `stats` (`0s`; log a one-line summary every so often, e.g. `10s`), `features` (`[]`; capabilities beyond the cosmetic ghost, every member of a room must list the same set), and `show_console` (`false`; open a window for a client a mod started silently).

## `server` — read by `meshghost-server.exe`

| Key | Shipped value | What it does |
|---|---|---|
| `listen_on` | `0.0.0.0:7777` | The tcp address and port to serve. This is the port to forward, both tcp and udp. |
| `listen_quic` | empty | Where quic listens. Empty reuses `listen_on`'s port number, so hosting means forwarding one number. |
| `listen_udp` | empty | Where the plain `udp` transport listens. Empty reuses `listen_on`'s port unless quic is served too, in which case udp moves aside to 7780 so quic keeps the shared number -- on `listen_on`'s own interface, so a relay bound to `0.0.0.0` serves udp there too. (It moved aside to *loopback* until 2026-09-08, which made the forwarding advice below unusable for a public relay.) |
| `transport` | `tcp,quic` | Which transports to serve at once, any of `tcp`, `udp`, `quic`. Clients on different transports share a room. |
| `tls` | `auto` | Encryption for tcp: `off`, `auto` (TLS and plaintext on the same port) or `required` (refuse plaintext). quic is always encrypted; plain udp never is. |
| `room_code` | empty | If set, every client must present it. |
| `only_game` | empty | Restrict the server to one game id (`emerald`, `crystal`, `tevi`, `pseudoregalia`). Empty hosts any game. |
| `ghost_collision` | `disabled` | The room-wide policy the server advertises: `enabled` or `disabled`. Advisory; a client may still turn its own off. |
| `max_clients` | `8` | Seats across all rooms. Connections that have not yet said hello are bounded separately, so a flood cannot use up the seats. |
| `send_hz` | `15` | How many times a second the server forwards each player's state to the room. |

| `resume_grace_seconds` | `0` | How long a dropped client's identity is held for a reconnect before the room is told it left. `0` (or absent) means the built-in 20 seconds. Only used by rooms that negotiated session resumption; a cosmetic room never holds anything. |

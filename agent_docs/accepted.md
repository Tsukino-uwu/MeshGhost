Accepted and Done
==================

Ideas that were taken up and BUILT, with the reasoning that led there. The mirror of
rejected.md: that file is things we decided not to do, this is things we decided to do and
then did.

WHY THIS FILE EXISTS: plans.md is about work that is live or planned, and bug.md is about
things that broke. Neither is a good home for "we considered this, chose it, and it now
exists" - so those entries either bloated plans.md with finished business or vanished into a
commit message nobody re-reads. This is where they land instead.

ACCEPTED MEANS BUILT, NOT AGREED. If something is decided but not yet implemented, it belongs
in plans.md - that is still future work. Moving a plan here loses the fact that it is
outstanding. The test is simple: can you point at the thing it produced?

WHAT STAYS ELSEWHERE:

- The DESIGN REASONING for a feature stays in plans.md next to the feature. This file
    records that an idea was accepted and what came of it, not a second copy of the design.
- Bugs found along the way stay in bug.md.
- A rejection belongs in rejected.md even if part of the idea was accepted; say so in both.

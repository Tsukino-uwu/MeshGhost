# Pokémon Crystal — flag register

<!-- line-cap: none -- register; size is the number of switches that exist. Why: agent_docs/claude-md-cap.md. -->

**A Lua adapter has no compile step**, so this adapter has no compile-time bools at all. Every
switch it has is a **runtime** one — an environment variable, a global set before the script is
`dofile()`'d, or a file sitting beside the script — and that makes the register more important
here, not less: a compile-time probe is compiled out of a shipped build, while a flag file only
needs someone to forget.

**This adapter writes game RAM** (object RAM only, never a save), so one of its switches lowers a
safety bar. It is `MESHGHOST_CRYSTAL_AP_TRY`, and it is the first row below for that reason.

It is not a description of how the game works — that is `documentation.md` — and not a list of
compensations, which is `BANDAGES.md`. A switch can appear in both; this one says what it is, that
one says what it costs.

**Everything here lives in `meshghost_crystal.lua`.** The probes have their own switches,
documented in each probe's header and indexed in [probes/README.md](probes/README.md).

## Runtime switches

| Switch | How it is set | Default when unset | What it does |
|---|---|---|---|
| `MESHGHOST_NO_AUTOSTART` | environment (any value) | unset — the adapter starts a core itself | Turns autostart OFF, so the adapter uses only a core that is already running and never spawns one. **Supported configuration, not a debug switch**: an antivirus objecting to one program launching another is a real thing that happens to real players, and this is the documented answer — set it and run `meshghost.exe` by hand. Every adapter honours the same name. |
| `MESHGHOST_CRYSTAL_AP_TRY` | `=1` in the environment, **or** a file named `ap_try.flag` beside the script | unset — a missing address **refuses to run** | **Lowers the bar from *measured* to *unconfirmed*, never to *invented*.** **As of 2026-08-19 the Archipelago table's `candidates` list is EMPTY** (`= {}` in source) — `0x015A` sat there as the leading `W_BATTLEMODE` candidate until a trainer battle refuted it — so today this switch reaches only the `W_BGMAPOFFSET*`-zero branch and the gate diagnostic, and can substitute nothing. The mechanism below is what it does when the list is repopulated: on a build whose address table still has a `nil`, it substitutes a **named candidate** from that table's own `candidates` list and logs `UNCONFIRMED ADDRESS IN USE` on every startup, so a session run this way can always be told apart from a measured one afterwards. A missing *candidate* still refuses. Two ways to set it because an environment variable needs a BizHawk restart and the emulator is usually already running by the time anyone decides to try; **deleting the file is how the experiment ends** -- or, better, RENAME it to `ap_try.flag.off`, which parks it inertly right where you will look for it next time instead of making you re-create it from memory. `.gitignore` covers both names; `release.yml` checks only the exact live name, so a parked flag cannot fail a build. It also turns on a twice-a-second gate diagnostic that prints what the gate decided *and what it decided from*. **`release.yml` fails the build outright if `ap_try.flag` reaches the package** — the flag is gitignored, so that check exists to catch a stray local copy. |
| `MESHGHOST_CRYSTAL_STRICT` | `=1` in the environment | unset — an untested ROM runs on vanilla's table after saying so in its first log line | Turns "untested build, running anyway" into a refusal. The permissive default is the user's call (2026-08-18): every non-vanilla ROM is attempted, and a wall of caution on each startup is noise. The one line still earns its place by **identifying** the build, so a misbehaving ghost has its ROM named at the top of the log. |
| `MESHGHOST_CRYSTAL_STATUS_ADDR` | environment, a number | `0x1439` on the Archipelago table | Overrides the Archipelago build's `wMapStatus` candidate so two addresses can be compared in one session. It exists because this address has a live history worth not repeating: `0x0FB1` survived two snapshot runs, then a live run showed it flickering between 2 and 1 several times a second while standing still — the snapshots had only ever agreed because they sampled while phase-locked. `0x1439` held `2` across 1103 samples of walking. **The gate needs the behaviour, not the name**; do not "correct" this to a tidier address on the strength of a published label. |
| `MESHGHOST_BRIDGE_PORT` | global first, then environment | unset — walk 7778-7785 | Pins the bridge port instead of walking it. An explicit port is honoured and then *not* walked: someone who names a port means that port, and silently landing somewhere else would be worse than failing. Readable as a global so a second instance can get its own port without restarting an already-open emulator. |
| `MESHGHOST_CRYSTAL_FORCE_PEER_SPRITE` | global first, then environment, a sprite id | unset — a ghost wears whatever the peer sent, falling back to the local player's sprite | **Probe, not behaviour.** Substitutes one sprite id for *every* peer, so "can a ghost wear a sprite this machine's player is not wearing" can be asked with one emulator and no peer of the other gender. Reaches BOTH tiers as of 2026-08-19 (it used to substitute only in the spawned path, which made a test of the cartridge path silently measure nothing). Pick any id: a resident one exercises the VRAM path, a non-resident one the cartridge path — a non-resident id now renders from cartridge graphics rather than falling back. Used on 2026-08-19 to establish the sprite id -> VRAM tile lookup: the ghost took `SPRITE_RIVAL`'s id and tile, matching byte for byte the engine's own object wearing that sprite. |
| `MESHGHOST_CRYSTAL_DRAW_OVERFLOW` | global first, then environment; `"0"` disables | unset — **ON** | **The drawn-overflow tier**, registered as a shipped compensation in [BANDAGES.md](BANDAGES.md). Peers the engine has no room for are painted over the emulator instead of not existing. **Default ON, where Emerald's equivalent is default OFF** — deliberate: Crystal's UI regions are locatable (a text box is the game's own frame tiles in the tilemap, a menu publishes `wMenuBorder*`), so a drawn ghost can be clipped out of them; Emerald's are not, so its tier would paint over text. |
| `MESHGHOST_CRYSTAL_OAM_OVERFLOW` | global first, then environment; `"1"` enables | unset — **OFF** | **The hardware tier**, the middle rung of spawned -> hardware -> drawn, added 2026-08-21 on the user's request. A peer whose tiles are resident in VRAM is written into the game's own sprite buffer (`wShadowOAM`, four entries of four bytes) so the PPU draws it: the game's live palettes including day/night and fades, ordering against the game's own cast, and no per-pixel Lua. Allocates DOWNWARD from entry 39 into the tail the engine left free (`hUsedSpriteIndex`), so the per-scanline limit drops a ghost rather than one of the game's characters; declines when there is no room or no frame has been learned for that facing, and the peer is painted instead — a peer never vanishes because a tier said no. **Stands down while `wStateFlags` bit 0 is clear**, which is the START menu clearing the buffer itself, and is the only occlusion it genuinely inherits. **It does NOT add capacity** (the engine already uses 34–36 of 40 entries outdoors and all 40 indoors — zero to one extra character) and **it does NOT get occlusion free**: a text box is background tiles with the BG-to-OAM priority bit clear, so a hardware sprite draws in FRONT of it, and this tier reuses the drawn tier's clipping rather than claiming otherwise. The priority bit is left clear deliberately — setting it would put the peer behind every non-zero background colour, i.e. behind the scenery it stands on. Off by default because nothing about how it LOOKS has been confirmed on screen (`UNVERIFIED.md`). |
| `MESHGHOST_CRYSTAL_UI_DEBUG` | environment (any value), **or** the global `MESHGHOST_CRYSTAL_UI_DEBUG = true` | unset — off | **Probe.** Dumps which peers the drawn tier actually painted, where they sat, and the rectangle it thought it was protecting, throttled to once every 15 draw frames and only while a text box or menu is open. Exists because a hidden-peer *count* cannot separate "21 hidden" from "21 hidden and 20 more painted straight over the panel". Read once per frame, never per peer; a global as well as an env var so it can be flipped without relaunching the emulator. |
| `MESHGHOST_SCRIPT_DIR`, `MESHGHOST_SCRIPT_DIR_CRYSTAL` | global first, then environment | unset — the script finds itself with `debug.getinfo` | Overrides where the adapter thinks it lives, which decides where it loads LuaSocket and writes its log. Set by whatever launched the script when it knows better. Registered late (2026-08-19) after an audit found it unregistered in both Lua adapters. |
| `MESHGHOST_DEV_LOADER` | global, set by `dev-scripts/bizhawk-dev-loader.lua` | unset — the adapter takes the frame loop | **Decides who owns the frame loop.** Set, the adapter hands its per-frame function to the loader instead of running `while true ... emu.frameadvance()`. Development only, and never set in a shipped configuration — the loader is not shipped. Emerald's register already carried this row; Crystal's did not until 2026-08-19. |
| `MESHGHOST_LOOPBACK_OFFSET_X` | global first, then environment | **`2`** | Dev-only, in tiles. Applied **only** to the `"<id>-ghost"` loopback echo, at its single use site in `syncGhost` — a real peer already stands where they stand and is never moved. That gate is why this can carry a nonzero default at all: before it (2026-08-25) the offset hit every peer, so `0` was the only value safe for a two-machine session. The default matches Emerald's `LOOPBACK_GHOST_OFFSET_TILES_X` at the user's request after a side-by-side run of both games — an exact trail hides the ghost behind the character, which is the thing being judged. Set `MESHGHOST_LOOPBACK_TRAIL` (to anything) to force `0` for that exact-trail mode; same env-var name and meaning in both games, so one variable switches either. Note this ghost is a real object event with real collision, so a nonzero offset also keeps it from spawning inside something solid. |
| `MESHGHOST_CRYSTAL_GHOSTS_PASSABLE` | global | unset — off | **Probe, dev only: nothing blocks, ever.** Both shipped passable rules are unreachable for a peer that is WALKING — the idle rule needs five seconds on one tile, the shove rule needs the player standing still and pressing into it — so a moving ghost blocks for as long as it keeps moving, and a bumped player stutters no matter how good the ghost is. Added 2026-08-23 to remove that confound while judging motion, after the user spotted the tell: *"it was perfect while the spawned ghost was standing still"*. **Note what it does, because it is not a collision flag — this adapter has none:** "not blocking" IS "rendered by the drawn tier" by design, so with this on a peer appears as a DRAWN ghost and there is no spawned copy to compare against. Turn it off to get the two tiers side by side. |
| `MESHGHOST_CRYSTAL_STEP_LAG` | global first, then environment; `"1"` enables | unset — off | **Probe, read-only: where the spawned ghost's step-start lag goes.** Times each step from the frame the local player committed to a tile, through the frame it came back through the core, to the frame `stepGhost` wrote it — so the wire and the adapter are separated by construction rather than by subtracting one from the total, which is how the previous split came to be wrong in both halves (`pitfalls.md`, 2026-08-23). **Loopback only**: off it there is no player frame to subtract, and it says so by counting those arrivals rather than averaging them in. Reports `spread` before `mean`, because a constant lag is invisible and a varying one is the stutter. Also makes the tier decision name itself when a peer stays drawn, which is what a count of `0 spawned` cannot do. Writes no game memory and changes no decision. |
| `MESHGHOST_COMPARE_TIERS` | **global first, then environment** (any value) | unset — off | **Probe, and the intended dev default for judging the drawn tier.** Renders the ONE loopback ghost **twice, in the same frame, from the same peer state**: spawned two tiles to the right, painted two tiles to the left. What the painted renderer is missing — engine occlusion, a cave's darkness, a water reflection, a doorway — is a question about a *place*, and flipping a flag between two runs cannot answer it because the place has changed by the time the other renderer is on. **Deliberately not gated on `MESHGHOST_CRYSTAL_DRAW_OVERFLOW`**: the point is to look at the drawn tier while it is shipped off, so with the tier off the loopback ghost is the only peer painted, and with it on it is painted in addition to the real overflow. It supplies its own **+3** for the spawned side whenever `MESHGHOST_LOOPBACK_OFFSET_X` resolves to 0 (i.e. under `MESHGHOST_LOOPBACK_TRAIL`); at the default 2 the spawned copy simply stays at +2, still clear of the painted copy at -2 — two ghosts on the player's tile is the comparison this exists to avoid. Never applies to a real peer: only `"<id>-ghost"` is duplicated. Announces itself as `PROBE FLAG IN USE` at startup, because two ghosts where a session expects one is otherwise indistinguishable from a duplicate-spawn bug. User's request, 2026-08-19. |
| `MESHGHOST_CRYSTAL_FREEZE_STATE` | global | unset — off | **Probe, and it CHANGES SHIPPED COLLISION.** Pins what this client *sends* to the first state it ever built, so a loopback peer stands still forever while the player moves — which is how "does the ghost track the peer, or is it just mirroring me?" gets asked with one emulator. **Registered here because of its second effect, which is easy to miss reading the send path alone:** it also forces `shouldBlock()` to return `true` unconditionally, bypassing both passable rules, on the reasoning that a frozen peer is by definition idle. So a session run with this on is judging a different collision rule from the shipped one. Pairs with `MESHGHOST_CRYSTAL_FROZEN` below. |
| `MESHGHOST_CRYSTAL_FROZEN` | global — but **set by the adapter, not by you** | unset | **Storage, not a switch**, and registered because it looks like one. It holds the state captured by `MESHGHOST_CRYSTAL_FREEZE_STATE` above. It is a **bare global rather than a local deliberately**: a local would be re-initialised on every script reload, and the point is to survive one. Setting it by hand pins the peer to a state you wrote rather than one the game produced. |

**No compile-time flags.** Two things do print in a normal run, both deliberately: the
experiment-mode gate line (gated behind `AP_TRY`, so silent unless asked for), and the drawn
tier's once-a-second summary of how many peers it painted and why the rest were not — which exists
because "half the screen is empty" needed a number separating "the peers never arrived" from "they
arrived and were not drawn" (2026-08-19).

## Behaviour — constants that decide what a player sees

| Constant | Value | What it decides |
|---|---|---|
| the address table | one per ROM build | **The biggest switch in the file, and it is a table rather than a flag.** `classifyRom()` picks `vanilla` or `archipelago` from the header title before anything reads or writes memory. Vanilla's entries come from our own hash-verified `pokecrystal` build; Archipelago's were each *measured*, because the patch moves WRAM non-uniformly (+7 for the coordinate block, +6 for the object array, −0x2A for the map-object table) and no constant offset recovers vanilla's. **A `nil` entry is a refusal, never a fallback** — falling back to vanilla's value for one entry would let the gate pass on a byte meaning something else and start writing object RAM at addresses nobody checked. **Two entries on the Archipelago table are still `nil`, not one:** `W_USEDSPRITES`, which switches a peer's own appearance off on that build, and `W_STATEFLAGS`, which **turns the hardware (OAM) tier off on that build** — a shipped-capability consequence that was recorded nowhere until 2026-08-25. Both are `nil`-means-off rather than `nil`-means-refuse, because neither is a write target. `W_BATTLEMODE` was measured on that build 2026-08-19 (`0x1234`) and is no longer a gap. |
| `HARDWARE_CHARACTER_LIMIT` | `10` | **The Game Boy's own ceiling**, not a preference: 40 sprite entries at 4 per overworld character. The adapter stops spawning there, so nothing it draws flickers, and peers past it go to the drawn tier. |
| `RESERVED_STRUCTS_FOR_THE_GAME` | `3` | Object structs ghosts may never take, so the game's own cast always has somewhere to go. Fixes a measured failure: a crowd of peers held 11 of 13 structs and an NPC one tile from the player was simply not drawn. |
| `GHOST_RANGE_TILES` | `8` | Beyond this a ghost gives its slots back, which is what the engine's own characters do. Also why an off-screen peer no longer blocks a tile you cannot see. |
| `IDLE_FRAMES_BEFORE_PASSABLE` / `PUSH_FRAMES_BEFORE_PASSABLE` | `300` / `30` | The collision policy, the user's design: a peer that has not CHANGED TILE for five seconds stops blocking (turning on the spot is not activity), and a peer somebody is shoving into stops blocking in half a second — which is how doorways clear without the adapter knowing where the doors are. |
| the first-2px step application | `±2` px | **A shipped compensation**, and registered as such in `BANDAGES.md`. The engine applies its own first pixel increment in the frame it initiates a step; ours starts a frame later, so without this every step lands 2 px short and the error accumulates. |
| `FLAG1_WONT_DELETE` | `0x02` | Set on every ghost, or the engine culls it as soon as it leaves the visible window. A fact about the game (`documentation.md`), not a dial. |
| `STANDING` / `MAPSTATUS_HANDLE` / `UNASSIGNED` | `255` / `2` / `0xFF` | Observed engine values. Changing one asserts a different fact about the game. |
| `GAME_ID` / `GAME_VERSION` | `"crystal"` / `"phase9"` | Protocol identity. `GAME_ID` must match the release's `games/pokemon/crystal/` folder name. |
| `DOMAIN` / `ROM_DOMAIN` | `"WRAM"` / `"ROM"` | Which BizHawk memory domain the adapter reads and writes. `System Bus` and `WRAM` were confirmed to reach the same bank-1 bytes and agree exactly (`domain_probe.lua`); `WRAM` is the one used. |
| `BRIDGE_HOST` | `"127.0.0.1"` | Fixed on purpose. An adapter may hold a socket to its own local core and nothing else. |
| `BRIDGE_BASE_PORT` / `BRIDGE_PORT_COUNT` | `7778` / `8` | The port walk, so two copies of the game on one machine each find their own core rather than silently sharing one. Shape copied from Pseudoregalia's `BridgeClient`, which is the version that has been tested. |
| `HELLO_ANSWER_FRAMES` | `90` (1.5 s) | **Silence is not acceptance.** Something that accepts a connection and never answers is far more likely an unrelated program holding a port in our range than a core, and committing to it would strand the session with no ghosts and no explanation. |
| `BUSY_PORT_COOLDOWN_FRAMES` | `600` (10 s) | A port whose core answered "busy" is a live core that simply is not ours; re-probing it every sweep is noise. |
| `RECONNECT_FRAMES` | `120` (2 s) | Retry cadence for a dropped bridge. |

## When a comment and a value disagree

Believe the value, then find out why the comment drifted before changing either.
And the harder version: **a flag flip is not a revert** — verify the switch disables the
*work*, not merely the decision the work feeds, or revert the commit instead.
[`agent_docs/pitfalls.md`](../../../../agent_docs/pitfalls.md#diagnostic-methodology) has the case that established it.

## Probe flags — off by default, and each announces itself when on

| Flag | Where set | What it does |
|---|---|---|
| `MESHGHOST_CRYSTAL_FACING_TRACE` | Lua global (`probes/flags_facing_trace.lua`) | Logs every frame the drawn tier's facing cache ACCEPTS — the facing, the tile view, the flip and the direction it was captured at — plus a `*** WRONG VIEW FOR THIS FACING ***` marker when one violates the invariant. Edge-triggered by construction: a facing accepts at most two frames, so it fires a handful of times a session and costs nothing per frame. File only, never `console.log`. **This is the instrument that found the 2026-08-22 facing bug after four fixes reasoned from the code had failed** — keep it, and reach for it first next time the drawn tier looks wrong. |

**A flag is set as a Lua global rather than an environment variable on purpose**: an environment
variable is fixed when the emulator starts, so it can only configure an instance you are about to
launch. A global can be set into an emulator that is already running and already in the state worth
measuring. `probes/flags_facing_trace.lua` sets every flag it owns explicitly, false included,
because the dev loader shares one Lua environment and "not mentioned" is not "off".
